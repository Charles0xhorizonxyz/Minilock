What the patch actually touches

One componentsmall patch

A ClockProviderPlugin implementation, plus the SystemUI change that lets plugins signed with your key load on a user build. The keyguard's layout, notifications, shortcuts and unlock flow are untouched — we only fill the slot AOSP already reserves for a clock.

No overlap problemsolved

The live wallpaper put the dial behind a big digital clock. As a clock plugin there is no second clock: AOSP hands us the slot and we render into it at whatever size we ask for.

Iterate without reflashingthe point

Build the OS once with the plugin hook. After that the dial ships as an ordinary APK, so new alloys, complications and layouts are a normal app update. Only GrapheneOS security releases need a rebuild, and your lock screen survives them.

Always-on displayfree

AOD asks the clock plugin for a dimmed, low-refresh variant. Ambient mode already is exactly that — dimmed dial, seconds hidden, one update a second, slow drift against burn-in. It maps straight across.

Drawn with Canvasports

The plugin returns a View, and WatchView is already a plain Canvas view, so the dial code moves into SystemUI essentially unchanged. These are the same routines drawing this mock.

What it costsbe clear

Unlocking the bootloader wipes the phone once. You hold your own signing keys and must back them up — losing them means another wipe. Each GrapheneOS security release needs a scripted rebuild and flash to stay current.
